# PaperPilot - 基于大模型与 Agent 架构的全流程科研助手

> 2026 全国高校 AI 大模型创新应用挑战赛（省赛）参赛作品
> 赛项：智领科研·意图驱动：基于大模型与 Agent 架构的全流程科研助手构建挑战赛

## 📖 项目简介
PaperPilot 是一款面向科研人员打造的全栈式智能科研助手 Agent。本项目突破了传统文献管理工具与简单对话 Chatbot 的局限，深度融合了大语言模型（LLM）的推理能力、Agent 智能路由架构与多文献检索增强生成（RAG）技术。系统致力于实现从多模态文献解析、抗幻觉问答、跨语言溯源，到图论挖掘与学术辅助的全流程科研闭环。

## ✨ 核心特性与赛项对应

### 🧠 Agent 架构与智能编排 (Agent Core)
- **双轨制 Intent Router（意图路由）**：针对大模型 Function Calling 的随机性，首创“前端正则拦截 + 后端 Tool 动态调度”双轨机制。当用户输入“生成论文框架”等强格式要求任务时，系统自动短路直达专属生成引擎，避免大模型多轮总结导致的格式崩坏，大幅降低延迟并提升系统鲁棒性。
- **CoT 思考链可视化**：在前端实时渲染 Agent 调用工具的思考过程（Thought -> Tool Call -> Tool Result），让黑盒推理过程完全透明，满足学术场景的“确定性”要求。

### [x] 模块一：多模态细粒度解析与去重
- **异步分批双引擎 PDF 解析**：基于 PyMuPDF 提取原生文本；针对扫描件，集成 RapidOCR 与云端 Vision 兜底。采用 **BackgroundTasks 与 Batching 架构**，降低 500+ 页长文档解析时的内存峰值与前端阻塞风险。
- **确定性算分与智能归因去重**：摒弃大模型直接估算的不稳定性，创新采用 `difflib` 序列比对算法计算绝对确定、可复现的物理相似度，再交由大模型进行深度语义归因（如精准定位 BLEU 分数从 41.0 提升至 41.8 的微观差异），并自动生成修订版预警。
- **智能目录过滤**：基于排版特征（如连续点号密度）自动识别并过滤长文档目录页，防止目录高频词汇干扰向量检索。

### [x] 模块二：抗幻觉 RAG 与精准溯源
- **Hybrid RAG（混合检索）**：结合 Dense 向量语义检索与 Sparse 动态正则实体硬匹配，覆盖长文档中微观参数（如 β1、0.98）的召回盲区。
- **物理级溯源与流式护栏**：文本切块强制注入物理页码标签，Prompt 最高指令约束回答附带 `[Page X]`。后端实现“流式拦截兜底”，并在触发拒答机制时自动阻断页码生成，严守学术严谨底线。

### [x] 模块三：双向联动阅读与划词三连击
- **双栏帧级联动**：基于 `requestAnimationFrame` 和物理防抖锁，实现中英双栏丝滑同步滚动，无死锁卡顿。
- **物理级防幻觉翻译**：前端独创正则级清洗机制，强制保留英文标题，斩断参考文献、图注及脚注被大模型误翻，保证翻译纯净度。
- **精准溯源跳转**：采用 DOM 倒序锚点劫持，点击正文 `[12]` 等引用，平滑滚动将文末文献对齐至屏幕中心，并提供 3 秒高亮反馈，模拟 IDE“跳转到定义”体验。
- **划词三连击**：精准捕捉划词位置，支持边缘碰撞自动翻转防遮挡，提供划词翻译、学术重写与中译英。

### [x] 模块四：arXiv 智能追踪与推荐
- **动态追踪与开源复现优选**：集成真实 arXiv API 抓取最新领域论文；结合本地库计算相关性，**优先推荐附带 GitHub 开源代码的论文**，并自动生成推荐理由（如“附带开源代码，复现性强”）。内置离线 mock 兜底库，保障断网情况下的系统高可用性。

### [x] 模块五：引用图谱挖掘与混合 RAG 综述生成
- **图论挖掘与零伪造兜底**：利用 NetworkX 构建引用有向图与 PageRank 权重挖掘。若长文档未能成功抽取参考文献，系统触发“零伪造”降级策略，绝不捏造保底数据，如实渲染单节点并给予文字预警。
- **混合检索策略（Hybrid RAG）**：采用“全局摘要物理召回 + 局部语义细节检索”双轨策略，生成零幻觉的全中文领域学术综述。

### [x] 模块六：数据可视化与学术写作 Copilot
- **智能 CSV 图表与 Caption**：自动识别数值列与递增序号，智能渲染折线图、分组柱状图、3D 雷达图等，并通过大模型基于真实统计量生成严谨的 Figure Caption。
- **References 白名单约束与 Mermaid/TikZ 渲染**：输入 Idea 自动生成 Markdown 论文框架、Mermaid 架构拓扑图及 TikZ 源码。首创 References 白名单机制，强制大模型引用必须匹配本地 ChromaDB 库中真实存在的文献，从底层杜绝伪造引用的学术不端行为。

### [x] 扩展模块：多文献管理与上下文隔离
- 前端构建 DocumentList 组件，支持多文献动态渲染、高亮切换与物理删除；后端通过 `doc_filter` 参数配合，实现多文献问答上下文的物理级隔离，杜绝“串台”。

## 🛠️ 技术栈选型
- **前端**：Next.js (App Router), React 19, TypeScript, ECharts (图谱渲染), Mermaid.js (拓扑渲染), KaTeX (公式), 现代深色学术风 UI
- **后端**：FastAPI (Python), Uvicorn, Tenacity (网络重试与熔断机制), `difflib` (文本相似度算法)
- **大模型与检索**：OpenAI 兼容 API（默认接入智谱 GLM-4，可通过 `BASE_URL` 切换）, LangChain Text Splitters
- **向量数据库**：ChromaDB (本地持久化)
- **文档与图像解析**：PyMuPDF (fitz), RapidOCR (本地离线多模态引擎), NetworkX (图论计算), Pandas & Matplotlib (数据可视化)

## 🏆 架构亮点
- **配置驱动与启发式规则相结合**：分块大小、去重阈值、目录过滤阈值、RAG Top-K、图谱 PageRank 降级参数、CSV 图表类型等关键参数集中在 `CONFIG` 中管理，减少散落硬编码；长文档目录过滤基于“点号密度 + 行数”启发式规则，微观实体抽取采用“正则稀疏召回 + LLM 结构化抽取”，图谱在 PageRank 异常时执行确定性降级，CSV X 轴通过“首列单调性检测”自动识别。上述策略均以真实 PDF/CSV 数据为输入，配合固定模型版本与参数配置，提升可复现性。
- **面向长文档的工程优化**：逐页解析 + 分块批写入 + 后台元数据提取 + 可配置批大小，降低百页 PDF 入库时的写入峰值与主流程阻塞；配合解析进度日志和 541 页书籍压测，验证系统在 500+ 页长文档上的稳定性。

### 已知限制

| 编号 | 问题 | 影响 | 处理 |
|---|---|---|---|
| B-01 | Vision OCR 不可用（当前模型不支持 `image_url`） | 影响低，RapidOCR 已覆盖扫描件 | 技术文档说明；如需更强扫描件识别，可切换多模态模型 |

1. **541 页纯文本解析**：峰值 5 MB、3.5 秒，不是瓶颈。
2. **541 页完整入库**：1780 块、200 OK、无 OOM、无前端超时，本地完整链路可用。
3. **目录过滤、分块批写入、后台元数据**：按预期执行。
4. **扫描件 OCR**：`v1_img.pdf` 15/15 页经 RapidOCR 全部识别成功，45 块、参考文献 20 条，扫描件演示可用。
5. **Vision OCR**：受当前纯文本模型限制不可用，属已知限制，但 RapidOCR 已覆盖扫描件，影响降低。
6. **去重与版本差异**：v7 → v1 重复预警、版本提示、覆盖、`/diff` 均通过，符合赛项版本演进测试用例。
7. **图谱、综述、Future Work、CSV、框架、arXiv、Agent**：本地全流程通过。
8. **长文档全文翻译**：功能可用但耗时与 token 成本高，演示需控制范围。

## 🚀 快速开始

### 1. 后端启动

```bash
# 进入 backend 目录并启动服务
cd backend

# 创建并激活虚拟环境 (Windows)
python -m venv venv
venv\Scripts\activate

# 安装依赖
pip install -r requirements.txt

# 启动服务
uvicorn main:app --reload --port 8000
```

### 2. 环境变量配置

在 backend 目录下创建 `.env` 文件，填入您的 API Key（请勿上传至公开仓库）：

```env
API_KEY=您的API_KEY
BASE_URL=https://open.bigmodel.cn/api/paas/v4/
```

`.env.example` 已提供变量模板，真实 `.env` 请加入 `.gitignore`。

### 3. 前端启动

进入 frontend 目录并启动：

```bash
cd frontend
npm install
npm run dev
```

访问 http://localhost:3000 即可体验系统。

> 公网部署时，前端需设置 `NEXT_PUBLIC_API_BASE_URL` 指向后端公网地址；后端需设置 `CORS_ORIGINS` 包含前端域名。详见后续部署说明。
